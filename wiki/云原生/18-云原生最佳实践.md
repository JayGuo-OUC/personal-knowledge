# 云原生最佳实践

## 学习目标
- 汇总从容器到生产的通用最佳实践
- 建立「声明式、不可变、弹性、渐进」的工程直觉

## 核心原则

云原生落地的几条主线，贯穿前面各主题。

## 详细说明

### 1. 不可变基础设施（Immutable Infrastructure）
镜像构建后不再修改，靠**重新构建+重新部署**来变更，而非登录机器改配置。见 [[04-Docker实战]]、[[08-Pod与工作负载]]。

### 2. 一切声明式（Declarative）
用 Git 中的 YAML 描述期望状态，让系统调谐（见 [[06-Kubernetes核心概念]]、[[11-控制器与编排原理]]、[[15-CI-CD与DevOps]] 的 GitOps）。

### 3. 资源请求与限制
为每个容器设置 requests/limits，避免「吵闹邻居」并支撑调度与弹性（见 [[08-Pod与工作负载]]）。

### 4. 健康检查
配置 liveness / readiness / startup 探针，让 K8s 正确重启与引流（见 [[07-Kubernetes架构]]）。

### 5. 弹性伸缩
用 HPA（基于 CPU/自定义指标）自动扩缩，配合 Metrics Server（见 [[14-可观测性]]）。

### 6. 渐进式交付
金丝雀 / 蓝绿 / 滚动发布，结合服务网格降低上线风险（见 [[13-服务网格ServiceMesh]]、[[15-CI-CD与DevOps]]）。

### 7. 可观测优先
上线前先接好指标/日志/追踪，问题可定位（见 [[14-可观测性]]）。

### 8. 安全左移
镜像扫描、最小权限、供应链签名，贯穿 CI 到运行（见 [[17-云原生安全]]）。

### 9. 成本优化
合理 requests、缩到零（Serverless，见 [[16-Serverless与FaaS]]）、闲置资源回收。

## 实践示例
一个生产级 Deployment 同时具备：资源限制、就绪探针、滚动更新策略、HPA——把上述原则组合落地。

## 常见问题
**Q：最佳实践是不是都要一次到位？**
A：不必。按团队成熟度渐进采用，从「声明式 + 健康检查 + CI/CD」起步最有效。
