# 存储与配置

## 学习目标
- 理解 Volume、PV、PVC 的关系
- 掌握 ConfigMap 与 Secret 的用法
- 了解 StorageClass 与 CSI

## 核心概念

容器文件系统是易失的，需要**存储**持久化数据；应用的**配置**与**密钥**应与镜像解耦。

## 详细说明

### Volume
Pod 内的存储挂载点，生命周期可与 Pod 相同（emptyDir）或更久（持久卷）。

### PV / PVC
- **PV（PersistentVolume）**：集群级别的存储资源（由管理员或 StorageClass 动态供给）。
- **PVC（PersistentVolumeClaim）**：用户对存储的「申请」。
```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata: { name: data }
spec:
  accessModes: [ReadWriteOnce]
  resources: { requests: { storage: 10Gi } }
```

### StorageClass 与 CSI
- **StorageClass** 描述存储「类型」（如 SSD/网络盘），支持动态供给。
- **CSI（Container Storage Interface）** 让任意存储后端以插件方式接入 K8s（见 [[05-容器运行时与OCI]] 类似的接口解耦思想）。

### ConfigMap
把配置以键值或文件形式注入容器：
```yaml
apiVersion: v1
kind: ConfigMap
metadata: { name: app-config }
data:
  LOG_LEVEL: info
```
注入方式：环境变量或挂载文件。

### Secret
存储敏感信息（密码、令牌、证书），默认 base64 编码（非加密，需配合加密 provider 或外部密钥管理，见 [[17-云原生安全]]）。

## 常见问题
**Q：ConfigMap 改了，容器会自动生效吗？**
A：挂载为文件的需等待同步或重启；环境变量形式需重建 Pod。
