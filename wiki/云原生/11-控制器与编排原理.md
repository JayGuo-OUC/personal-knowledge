# 控制器与编排原理

## 学习目标
- 理解「调谐循环（Reconcile Loop）」核心思想
- 理解声明式 API 如何实现自愈
- 了解 Operator 与 CRD 的扩展机制

## 核心概念

K8s 的编排本质是**不断把实际状态拉向期望状态**的控制循环，由一批控制器协作完成。

## 详细说明

### 调谐循环（Reconcile Loop）
每个控制器持续做三件事：
1. **观察**实际状态（通过 API Server 监听 etcd 变化）。
2. **对比**期望状态（用户声明的 YAML）。
3. **行动**消除差异（创建/删除/扩容）。

这就是 K8s **自愈**的来源：Pod 挂了，副本控制器会自动补一个。

### 声明式 API
用户只声明「想要什么」，不关心「怎么做」。系统负责达成并维持。这种解耦让自动化成为可能（见 [[06-Kubernetes核心概念]]）。

### 控制器模式
- 内建控制器：ReplicaSet、Deployment、Node、Endpoints 等（见 [[08-Pod与工作负载]]）。
- 所有控制器都遵循同一模式，互不冲突、各管一块。

### CRD 与 Operator
- **CRD（Custom Resource Definition）**：扩展 K8s API，定义你自己的资源类型。
- **Operator**：为特定应用（如数据库、消息队列）编写**自定义控制器**，把运维知识代码化，实现复杂应用的一键部署与运维。

### 对比命令式编排
传统脚本是「一次性命令」；K8s 是「持续维持状态」，因此更 resilient。

## 实践示例
查看某控制器的调谐信息：
```bash
kubectl describe deployment web   # 看 Events 中的调谐记录
```

## 常见问题
**Q：Operator 和普通 Deployment 区别？**
A：Operator 通过 CRD + 自定义控制器，封装领域运维逻辑（如主从切换、备份），而不仅仅是跑容器。
