# 云原生概览

## 学习目标
- 理解「云原生」的定义与由来
- 掌握云原生的四大核心特征
- 明白云原生与传统架构、与传统云计算的区别

## 核心概念

**云原生（Cloud Native）** 是一套构建和运行应用程序的方法论，充分利用云计算的弹性、分布式优势，让应用具备**弹性、可扩展、容错、快速交付**的能力。

云原生计算基金会（CNCF）给出的定义：云原生技术有利于在**公有云、私有云、混合云**等动态环境中构建和运行可弹性扩展的应用；代表技术包括**容器、服务网格、微服务、不可变基础设施和声明式 API**。

## 详细说明

### 四大核心特征
1. **微服务（Microservices）**：把单体应用拆成一组松耦合、可独立部署的小服务。见 [[12-微服务架构]]。
2. **容器（Containers）**：以标准化方式打包应用及依赖，实现环境一致。见 [[03-容器技术基础]]。
3. **DevOps / 持续交付**：开发与运维协作，自动化构建、测试、发布。见 [[15-CI-CD与DevOps]]。
4. **弹性基础设施 / 持续交付流水线**：基于声明式 API 与自动化编排（典型如 Kubernetes）。见 [[06-Kubernetes核心概念]]。

### 为什么需要云原生
- 业务需要**快速迭代**、**高可用**、**按需扩缩容**。
- 传统单体 + 手工运维难以应对规模与变更频率。
- 云原生让团队**小步快跑**，故障**隔离且自愈**。

### 云原生 ≠ 上云
把原有应用直接搬到虚拟机上，并不等于云原生。云原生更强调**为云而设计**的架构与工程实践。

## 常见问题
**Q：云原生一定要用 Kubernetes 吗？**
A：K8s 是当前事实标准，但云原生是一种理念。小团队也可先从容器 + CI/CD 起步。

**Q：学习成本很高怎么办？**
A：按 [[19-学习路线与资源]] 的路线图循序渐进，先懂容器，再学 K8s。
