# 可观测性

## 学习目标
- 掌握可观测性三支柱：指标 / 日志 / 追踪
- 理解黄金信号（Golden Signals）
- 了解 Prometheus、Grafana、EFK、OpenTelemetry 等工具

## 核心概念

**可观测性（Observability）** 指通过系统外部输出（指标、日志、追踪）推断内部状态的能力。云原生分布式系统尤其依赖它（见 [[12-微服务架构]]）。

## 详细说明

### 三支柱
1. **Metrics（指标）**：数值时间序列，如 QPS、CPU、错误率。代表：**Prometheus**（采集）+ **Grafana**（展示）。
2. **Logs（日志）**：结构化/非结构化事件记录。栈：**EFK/ELK**（Elasticsearch + Fluentd/Filebeat + Kibana）。
3. **Traces（追踪）**：一次请求跨多个服务的调用链。代表：**Jaeger**、**OpenTelemetry**。

### 黄金信号（Golden Signals）
- **Latency（延迟）**：请求耗时。
- **Traffic（流量）**：系统负载（QPS）。
- **Errors（错误率）**：失败比例。
- **Saturation（饱和度）**：资源使用接近上限程度。

### SLI / SLO / SLA
- **SLI**：服务水平的量化指标（如可用性 99.9%）。
- **SLO**：你承诺的目标。
- **SLA**：带违约后果的对外协议。

### OpenTelemetry
统一采集指标、日志、追踪的开放标准与 SDK，避免厂商锁定。

### 与 Prometheus 的关系
Prometheus 拉取（pull）各组件暴露的 `/metrics` 端点，结合 K8s 服务发现（见 [[09-Service与网络]]）自动抓取。

## 实践示例
Prometheus 抓取配置片段：
```yaml
scrape_configs:
  - job_name: kubernetes-pods
    kubernetes_sd_configs: [{ role: pod }]
```

## 常见问题
**Q：有了日志还需要追踪吗？**
A：需要。日志看单点，追踪看跨服务全链路，互补定位复杂问题。
