# Skill 的作用原理

## 摘要

Skill 的底层机制出乎意料地平庸：**扫描目录 → 把 `name + description` 拼进系统提示词 → 模型语义匹配 → 命中就读取完整文件 → 按需执行脚本或读引用**。没有向量检索，没有微调，没有特殊 API。它的全部效力来自「被加载进上下文后模型的指令遵循能力」——**Skill 不改变模型权重，只改变上下文**。

## 正文

### 完整时序

```
① 启动扫描
   Agent 遍历已知目录（.cursor/skills/、~/.cursor/skills/、.agents/skills/ …）
   找到所有 SKILL.md，解析 frontmatter
        ↓
② 注入系统提示词（仅 L1）
   把每个技能的 name + description 拼进 system prompt
   此时成本约 100 token/技能，正文一个字都没读
        ↓
③ 语义路由
   用户输入 → 模型拿它跟所有 description 做匹配
   「这次任务要不要用某个技能？」
        ↓
④ 加载正文（L2）
   命中 → 读取 SKILL.md 全文，追加进上下文
   之后的推理都受这份指令约束
        ↓
⑤ 按需展开（L3）
   正文说「跑 scripts/deploy.sh」→ 执行，只拿回结果
   正文说「详见 references/API.md」→ 读文件
        ↓
⑥ 产出
   按技能规定的步骤、格式、边界输出
```

### 关键洞察：「语义路由」是模型干的，不是代码干的

这点很多人误解。Agent **不是**用正则匹配关键词、**不是**用 embedding 检索来决定用哪个技能——它就是把所有描述列出来，让**模型自己读一遍然后判断**。

推论：

| 推论 | 说明 |
|------|------|
| **描述写得像人话就有用** | 模型理解的是语义，不需要塞满关键词做 SEO |
| **触发有不确定性** | 同一句话可能这次触发、下次不触发；这是概率模型的固有属性 |
| **不确定时可以用 `/` 强制调用** | 绕过语义路由，明确指定 |
| **模型越强，路由越准** | 弱模型会漏触发、误触发 |

### Skill 影响 Agent 的四个层面

| 层面 | 机制 | 具体例子 |
|------|------|---------|
| **知识注入** | 把模型没有的领域/组织知识塞进上下文 | 「本项目的测点命名规范是 `设备编码_信号类型_序号`」 |
| **流程约束** | 规定有序步骤与检查点 | 「1. 跑测试 2. 构建 3. 部署 4. 验健康检查，任一步失败立即停止」 |
| **工具策略** | 指定用哪个脚本/命令，禁止自由发挥 | 「用 `scripts/migrate.sh`，不要手写 SQL」 |
| **输出契约** | 规定产物格式 | 「报告必须含：风险等级、文件:行号、修复建议三段」 |

### 为什么「只是文件系统 + 提示词」却有效

三个原因：

1. **上下文就是一切**。给对了上下文，现役强模型的指令遵循能力已经足够好。
2. **可组合**。多个技能可同时加载，互不干扰（前提是技能设计时不假设「只有我一个」）。
3. **可确定性兜底**。不确定的部分用自然语言（模型判断），确定的部分用脚本（每次一样）。这是 Skill 比「一堆提示词模板」强的地方。

对比：

| 手段 | 改的是什么 | 成本 | 灵活度 |
|------|-----------|------|--------|
| 微调 | 模型权重 | 高，不可逆 | 低 |
| RAG | 运行时检索 | 中（要搭检索） | 中 |
| **Skill** | **上下文** | **低（纯文件）** | **高（随时改，即时生效）** |
| MCP | 工具/数据接入 | 中（要写服务） | 高 |

### 失效模式（以及排查）

| 症状 | 原因 | 排查 |
|------|------|------|
| **技能从不触发** | `description` 太空泛或没写「何时用」 | 用 `/skill-name` 显式调用验证技能本身没问题；没问题就改 description |
| **误触发**（不该用时出现） | description 里的关键词太宽泛 | 收窄描述，或加 `paths` 限定文件范围 |
| **加载了但不照做** | 正文太长被稀释；或指令有歧义 | 精简到 500 行内；检查有没有互相矛盾的指令 |
| **脚本跑不动** | 依赖缺失、路径写死、权限不足 | 脚本头部写清依赖，用相对路径，加错误提示 |
| **改了不生效** | 技能在会话启动时扫描 | 开新会话；Cursor 里 `/` 能发现新技能但保险起见重启 |
| **跨机器行为不一致** | 全局技能不会同步到云端/远程 Agent | 团队规范放**项目级** `.cursor/skills/` 并进 git |

### 可观测性

Cursor 里技能被应用时，Agent 的推理轨迹（trace）里能看到；用 Custom Mode 时输入框会显示徽章。判断「到底用没用上」最可靠的方式是**直接问 Agent**：

> 「你刚才用了哪个 skill？把它的 description 原样念出来。」

念得出来 = 确实加载了。
