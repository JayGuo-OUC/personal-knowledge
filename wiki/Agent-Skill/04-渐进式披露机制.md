# 渐进式披露机制

## 摘要

Skill 采用**三层渐进式加载**：启动时只加载所有技能的 `name + description`（约 100 token/个），任务匹配时才加载 `SKILL.md` 正文（建议 <5000 token / 500 行），正文引用的脚本和文档**按需再读**。这是 Skill 相对 Rules 的核心优势——20 条常驻规则每次请求都烧上下文，20 个技能只花 20 行描述，只有命中的那个才展开。

## 正文

### 三层模型

```
┌─ L1 元数据（~100 token/技能，启动时全量加载）
│    name: code-review
│    description: 评审代码…
│    ↓ 语义匹配命中
├─ L2 正文（<5000 token，命中才加载）
│    SKILL.md 全文：步骤、规范、示例、边界
│    ↓ 正文指向某个文件
└─ L3 资源（按需，用到才读）
     scripts/deploy.sh      → 直接执行，不进上下文
     references/REFERENCE.md → 需要时才读
     assets/template.json    → 需要时才读
```

| 层级 | 内容 | 时机 | 成本 |
|------|------|------|------|
| L1 | frontmatter 的 `name` + `description` | Agent 启动 | ~100 token/技能 |
| L2 | `SKILL.md` 正文 | 判定相关后 | 建议 <5000 token |
| L3 | `scripts/`、`references/`、`assets/` | 正文指向或任务需要时 | 按需 |

### 为什么这很重要：上下文经济学

假设你有 20 份团队规范：

| 方案 | 每次请求的固定成本 | 命中时成本 |
|------|------------------|-----------|
| 全塞进 Rules（常驻） | 20 × 500 token = **10,000 token** | 同上 |
| 做成 20 个 Skill | 20 × 100 token = **2,000 token** | + 命中的那 1 份 500 token |

**差距 5 倍**，而且技能越多差距越大。上下文是 LLM 应用最稀缺的资源——塞得越满，模型的指令遵循能力衰减越明显（"lost in the middle" 效应）。

### 三个关键推论

**① `description` 是「索引」，不是「简介」**
它承担了 100% 的召回职责。写得太泛（`处理代码`）→ 永不命中；写得太窄 → 该命中时不命中。见 [[03-SKILL.md结构与frontmatter详解]]。

**② 脚本不进上下文，这是白送的能力**
`scripts/` 里的 Python/Bash 代码**只有执行结果进上下文，源码不进**。所以：
- 复杂但确定性的逻辑（解析、转换、校验）→ 写脚本，几乎零上下文成本
- 需要模型判断的部分（分析、决策、生成）→ 写 Markdown

一句话：**判断交给模型，确定性交给脚本。** 这是 [[08-如何写出好Skill]] 的核心原则。

**③ 正文不是越长越好**
正文一旦加载就是**全量**进上下文。写 800 行，等于每次命中都烧掉一大块上下文，还可能稀释模型对关键指令的注意力。

### 设计准则

| 准则 | 具体做法 |
|------|---------|
| 正文 < 500 行 | 超了就拆 |
| `references/` 按主题拆小文件 | `api-guide.md`、`examples.md`，不要一个巨型 `ALL.md` |
| 引用只深一层 | `references/foo.md` ✅；`references/a/b/c.md` ❌ |
| 避免引用链 | A.md → B.md → C.md 会让 Agent 读很多轮 |
| 脚本自包含 | 依赖写清楚，别让 Agent 猜 |
| 模板放 `assets/` | 需要时才读，且可直接复制 |

### 常见反模式

| 反模式 | 后果 | 修法 |
|--------|------|------|
| SKILL.md 2000 行 | 命中一次烧掉大量上下文 | 拆 `references/` |
| 所有细则塞正文 | 关键指令被稀释 | 只留主干，细则外置 |
| `references/` 里再套 `references/` | 读引用链绕晕 | 拍平到一层 |
| description 写得太省 | 永不触发，技能形同虚设 | 补触发关键词 |
| 把可执行逻辑写进 Markdown 让模型照抄 | 每次结果不一致 | 抽成脚本 |
