# 实战技能包六件套

## 摘要

面向**强合规企业（政府 / 工业 / 水务，代码与数据不出境）**的 Cursor 起始技能包，共 6 个技能，已实际安装到 `~/.cursor/skills/`。覆盖「写代码 → 提交 → 评审 → 留痕 → 排障 → 重构」的完整链路，其中 `data-compliance-guard` 是合规红线守卫，带一个可直接跑的 Python 扫描脚本。

## 正文

### 包的位置

| 位置 | 路径 | 用途 |
|------|------|------|
| **源（可版本化、可分发的正本）** | `skills/cursor-agent-skills/` | 进 git，团队共享 |
| **安装位置（副本）** | `C:\Users\<用户名>\.cursor\skills\` | Cursor 实际加载处 |

改技能改**源**，改完重新复制安装（或直接在项目级目录里改）。

### 六件套总览

| 技能 | 目录 | 干什么 | 何时触发 | 带脚本？ |
|------|------|--------|---------|---------|
| **数据合规守卫** | `data-compliance-guard/` | 扫数据出境、密钥、个人信息、日志泄露 | 提交前 / 引依赖前 / 评审 AI 代码前 | ✅ `scan-egress.py` |
| **代码评审门禁** | `code-review-gate/` | 六维评审 + 留痕报告 | 要求评审 / PR 前 | ❌（有 references） |
| **AI 代码留痕** | `ai-code-provenance/` | AI 产出标注、提示词摘要、评审确认 | AI 生成代码后、提交前 | ❌ |
| **规范化提交** | `commit-and-pr/` | Conventional Commits + PR 模板 | 要提交 / 开 PR | ❌ |
| **系统化排障** | `debug-systematically/` | 复现→二分→根因→最小修复→回归测试 | 报错 / 有 bug | ❌ |
| **安全重构** | `refactor-safely/` | 先补测试网，小步提交，行为不变 | 要重构 / 大改 | ❌ |

### 链路：它们怎么串起来

```
         ┌──────────────────────────────────────────┐
         │  日常开发循环                              │
         └──────────────────────────────────────────┘

  写代码（AI 辅助）
      │
      ├─→ ai-code-provenance   标注 AI 产出 + 提示词摘要
      │
      └─→ data-compliance-guard  合规扫描（红线）
                │
                ├─ ❌ 有阻断项 → 修到通过
                ↓
  提交前
      │
      ├─→ code-review-gate     六维评审 + 报告落盘
      │
      └─→ commit-and-pr        规范 commit + PR 描述
                │
                ↓
  遇到问题
      ├─→ debug-systematically  复现 → 二分 → 根因 → 回归测试
      └─→ refactor-safely       先补测试网，再小步重构
```

### 逐个说明

#### 1. `data-compliance-guard` —— 合规红线守卫（核心）

**为什么放第一个**：强合规场景下，这是唯一「不通过就不能往下走」的门禁。

- **五条红线**：代码数据不出境 / 密钥不进仓库 / 个人信息不明文 / 客户数据不回传 / 错误日志不泄露
- **自动扫描**：`python scripts/scan-egress.py <路径>`，覆盖境外域名、硬编码凭据、个人信息、连接串、外发指令、日志泄露、境外云区域
- **人工补充**：新增依赖是否合规、是否带遥测、云区域、构建产物外链、字体图标来源
- **输出**：结构化报告 + 每个阻断项的可执行替换方案

**脚本设计要点**：
- 纯 Python 标准库，**零依赖、零网络请求**，可放心审读
- 已通过正反例验证：`req.body` 整体打印会命中，`req.body.userId` 白名单取字段不命中；`maskPhone(...)` 脱敏写法不误报；`example.cn` 等境内/内网域名不误报
- 退出码 `0` 通过 / `1` 有高危 —— 可直接接 CI

#### 2. `code-review-gate` —— 六维评审门禁

六维：**安全 / 敏感信息泄露 / 合规 / 性能 / 可维护性 / 依赖**

- 严重度分 Blocker / Major / Minor / Nit，Blocker 一票否决
- **报告必须落盘**到 `output/评审-*-YYYY-MM-DD.md`（审计要求）
- 详细检查项在 `references/review-checklist.md`，含每维的代码正反例
- 专门列了**「评审 AI 生成代码的额外检查项」**：幻觉依赖、幻觉 API、过度设计、静默兜底、假装验证

#### 3. `ai-code-provenance` —— AI 代码留痕

- 代码内声明：`@ai-generated` / `@ai-modified` + 模型 + 日期 + 提示词摘要 + 评审人
- 留痕记录落盘 `output/AI代码留痕-YYYY-MM-DD.md`
- commit message 里带 `AI-assisted:` 与 `Reviewed-by:`
- **铁规矩**：评审人必须真人署名，未评审标 `pending`，不得冒充

#### 4. `commit-and-pr` —— 规范化提交与 PR

- Conventional Commits 格式 + type 速查表
- 判断并拆分过大的改动（混了重构+新功能+修 bug 必须拆）
- PR 模板含「AI 辅助情况」与「怎么验证的」段
- 明令禁止 `git add .`

#### 5. `debug-systematically` —— 系统化排障

六阶段：**复现 → 二分定位 → 根因 → 最小修复 → 回归测试 → 报告**

- 铁律：**没有复现，就没有修复**
- 用 `git bisect` / 删代码法 / 打点法缩小范围，每步要有证据
- 区分症状与根因，连问五个为什么
- **每个修复都要有一个「修复前会失败」的测试**

#### 6. `refactor-safely` —— 安全重构

- 铁律：**重构不改变外部行为**（变了就是重写，走需求流程）
- **没测试网不许重构**，先补行为快照测试
- 小步提交：改一点 → 跑测试 → 通过 → 提交；不通过就 revert
- 明确禁止：重构中改行为 / 修 bug / 加功能

### 落地建议

| 阶段 | 动作 |
|------|------|
| **第 1 周** | 只装 `data-compliance-guard` + `commit-and-pr`，跑顺 |
| **第 2-3 周** | 加 `code-review-gate` 与 `ai-code-provenance`，把评审和留痕变成习惯 |
| **第 4 周起** | 加 `debug-systematically` 与 `refactor-safely` |
| **持续** | 按团队反馈迭代 description 与检查项；改动走 PR |

不要一次全上——**技能的采纳率比数量重要得多**。

### 自定义

这套包是**模板**，真正有价值的是你们团队自己的内容：

1. 把 `review-checklist.md` 里的检查项换成你们踩过的坑
2. 把 `data-compliance-guard` 的红线换成公司的数据分级标准
3. 把 `commit-and-pr` 的 type 表对齐你们现有的约定
4. 用 `/create-skill` 把你们特有的流程（如发布流程、现场部署流程）补进来
