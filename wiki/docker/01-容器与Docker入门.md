# 01 容器与 Docker 入门

## 摘要

Docker 是当下最主流的**容器化平台**。它把「应用 + 运行环境」打包成一个可移植、可复现的标准单元（容器），让你在开发、测试、生产环境之间「一次构建，到处运行」。本文讲清容器是什么、为什么比虚拟机更轻、以及 Docker 的整体工作方式。

## 正文

### 1. 为什么需要容器

传统部署的常见痛点：

- **环境不一致**：「在我机器上能跑」——开发、测试、生产环境差一点就出 bug。
- **依赖地狱**：A 应用要 Python 3.8，B 应用要 Python 3.11，装在一起互相冲突。
- **扩容慢**：新机器要重装一堆环境才能跑服务。
- **资源浪费**：每台虚拟机都带完整操作系统，开销大。

容器的答案：**把应用和它依赖的一切（库、配置、运行时）封进一个隔离的盒子，盒子在哪台机器上跑，行为都一致**。

### 2. 容器 vs 虚拟机

这是最常被问到的问题。关键区别在于**隔离层级**：

```
虚拟机（VM）：
  硬件 → Hypervisor →  Guest OS → 运行时 → 应用
  每个 VM 都有自己完整的操作系统内核，重量级（GB 级）。

容器（Container）：
  硬件 → 宿主 OS 内核 → 容器引擎(Docker) → 应用+依赖
  容器共享宿主内核，只打包应用与用户态依赖，轻量级（MB 级）。
```

| 维度 | 虚拟机 | 容器 |
|------|--------|------|
| 启动速度 | 秒~分钟级 | 毫秒~秒级 |
| 占用空间 | 几百 MB ~ 几 GB | 几 MB ~ 几百 MB |
| 隔离性 | 强（内核级隔离） | 较弱（共享内核，靠 namespace/cgroup） |
| 密度 | 一台机几十个 | 一台机几百上千个 |
| 性能损耗 | 有（虚拟化开销） | 极低（接近原生） |

> 结论：容器不是来取代虚拟机的，二者常配合使用——云厂商先用虚拟机隔离租户，再在虚拟机里跑容器。

### 3. Docker 是什么

Docker 是一套**容器工具链**，核心是 Docker Engine，包含：

- **Docker 守护进程（dockerd）**：后台服务，真正创建/管理容器。
- **Docker CLI（docker）**：你敲的命令，把请求发给守护进程。
- **容器镜像（Image）**：只读模板，容器的「蓝图」。
- **容器（Container）**：镜像运行起来的实例。
- **仓库（Registry）**：存镜像的地方（如 [[13-Docker-Hub与私有仓库|Docker Hub]]）。

> 形象比喻：镜像像「类」，容器像「对象实例」；镜像像「安装包」，容器像「装好并运行起来的软件」。

### 4. Docker 怎么工作的（核心原理）

Docker 用 Linux 内核的两大能力实现隔离：

- **Namespace**：做「视野隔离」——让容器以为自己独占进程、网络、文件系统、用户。
- **Cgroup（Control Group）**：做「资源限制」——限制容器能用多少 CPU、内存、IO。

> Windows/macOS 上 Docker Desktop 其实是起了一个轻量 Linux 虚拟机（如 WSL2 / HyperKit），容器仍跑在 Linux 内核上。所以 Docker 原生只跑 Linux 容器，Windows 容器是另一套（极少用）。

### 5. 一个最小上手示例

装好 Docker 后（见 [[02-安装与环境配置]]），跑：

```bash
# 拉取并运行官方 hello-world 镜像
docker run hello-world
```

它会：本地没有镜像 → 自动从 Docker Hub 拉取 → 启动容器 → 打印欢迎语 → 退出。一条命令体验「镜像变容器」。

再看一个持续运行的服务：

```bash
# 跑一个 nginx，把宿主 8080 端口映射到容器 80 端口
docker run -d -p 8080:80 --name my-nginx nginx
# 浏览器打开 http://localhost:8080 即可看到 nginx 默认页
```

### 6. 学习建议

- 概念先建立，再动手：建议接着读 [[03-镜像容器仓库核心概念]]。
- 直觉培养：把每个容器当成「一台极简、临时、一次性」的小机器。
