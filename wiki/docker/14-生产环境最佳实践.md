# 14 生产环境最佳实践

## 摘要

本地能跑 ≠ 生产稳。本文给出上生产前的 checklist：最小镜像、非 root 运行、资源限制、健康检查、日志与重启策略、安全加固，以及与 CI/CD 的集成思路。

## 正文

### 1. 镜像最小化

- 用 `-slim` / `alpine` / `distroless` 基础镜像。
- 多阶段构建，最终镜像不含编译工具链（见 [[07-Dockerfile完全指南]]）。
- 定期扫漏洞并升级基础镜像（见 [[13-Docker-Hub与私有仓库]]）。

### 2. 以非 root 用户运行

```dockerfile
RUN useradd -m appuser
USER appuser
```

> 容器内 root ≠ 宿主 root（有隔离），但仍是好习惯：一旦容器被突破，限制其权限。配合 `--cap-drop ALL` 进一步降权。

### 3. 资源限制（防止「一个容器吃满整机」）

```bash
docker run -d --memory 512m --cpus 1.0 --pids-limit 200 myapp:1.0
```

Compose 里写在 `deploy.resources.limits`（见 [[11-Docker-Compose编排]]）。

### 4. 健康检查

- Dockerfile 写 `HEALTHCHECK` 或用 Compose `healthcheck`。
- 让编排系统/负载均衡知道容器「进程在 ≠ 服务可用」。
- 配合 `depends_on: service_healthy` 控制启动顺序（见 [[12-实战全栈应用编排]]）。

### 5. 重启策略

```bash
docker run -d --restart unless-stopped myapp:1.0
```

| 值 | 含义 |
|----|------|
| `no` | 不自动重启（默认） |
| `on-failure` | 非 0 退出才重启 |
| `always` | 永远重启（含手动 stop 后宿主重启也会起） |
| `unless-stopped` | 除非手动 stop，否则一直重启（**最常用**） |

### 6. 日志管理

- 默认 `json-file` 日志驱动会无限增长，生产应限制或换驱动：

```bash
docker run -d --log-driver json-file --log-opt max-size=10m --log-opt max-file=3 myapp
```

- 更优：接 `fluentd` / `loki` / ELK，集中收集（与可观测性体系打通）。

### 7. 密钥与配置

- **绝不**把密码写进镜像或提交到代码库。
- 用环境变量（`.env` 不入库）或 secret 机制。
- Docker Swarm / K8s 有原生 secret；单机可用只读 bind mount 挂秘钥文件。

### 8. 只读文件系统

```bash
docker run -d --read-only --tmpfs /tmp myapp:1.0
```

> 进一步缩小攻击面：容器文件系统只读，仅 `tmpfs` 可写。

### 9. 固定版本，不用 latest

- 镜像标签锁定具体版本（见 [[13-Docker-Hub与私有仓库]] 标签策略）。
- 升级走「构建新版本 → 验证 → 切换」，保证可回滚。

### 10. 与 CI/CD 集成

典型流水线：

```
代码提交 → CI 构建镜像 → 跑测试 → 扫漏洞 → 打标签推送仓库 → 生产 pull 新镜像重启
```

- GitHub Actions / GitLab CI 里用 `docker/build-push-action` 构建并推送。
- 生产部署可用 `docker compose pull && docker compose up -d` 或交给 Kubernetes。

### 11. 上生产线前自查清单

- [ ] 镜像最小化 + 漏洞扫描通过
- [ ] 非 root + 资源限制
- [ ] 有 HEALTHCHECK + 重启策略
- [ ] 日志有限制/集中
- [ ] 密钥外置不入库
- [ ] 标签锁定版本可回滚
- [ ] 数据挂了 Volume（见 [[09-数据持久化Volume与挂载]]）
- [ ] 网络按需隔离（见 [[10-容器网络]]）
