# 10 容器网络

## 摘要

容器要互通、要被访问，就要懂 Docker 网络。本文讲清四种网络驱动（bridge / host / none / overlay）、默认 bridge 与自定义 bridge 的区别、端口映射原理，以及容器之间如何按名字互相访问。

## 正文

### 1. Docker 网络驱动一览

| 驱动 | 说明 | 场景 |
|------|------|------|
| **bridge（桥接）** | 默认驱动，容器接到虚拟网桥，互相隔离但有独立 IP | 单机多容器（最常用） |
| **host（主机）** | 容器直接共享宿主网络栈，无独立 IP | 追求网络性能、少一层 NAT |
| **none** | 容器无网络 | 纯计算、不需要联网 |
| **overlay** | 跨多台主机的虚拟网络 | Swarm / 多机集群（进阶） |
| **macvlan** | 给容器分配真实 MAC/ IP，像物理机 | 特殊网络需求（少用） |

### 2. 默认 bridge 网络

```bash
docker network ls                  # 列出网络，默认有 bridge/host/none
docker run -d --name web nginx     # 默认接在 bridge 上
docker inspect web | grep IPAddress   # 看容器获得的 172.17.x.x 内网 IP
```

默认 bridge 的局限：**容器之间不能用名字互访**，只能靠 IP（IP 还可能变）。所以实际开发几乎都用**自定义 bridge**。

### 3. 自定义 bridge 网络（推荐）

```bash
docker network create mynet          # 建一个自定义桥接网络
docker run -d --name web --network mynet nginx
docker run -d --name app --network mynet myapp:1.0
```

> 在自定义 bridge 上，容器**可以用名字互相访问**：`app` 容器里 `ping web` 直接通（Docker 内置 DNS）。多容器协作（如 web 连 db）就靠它。

### 4. 端口映射（对外暴露）

容器有内网 IP，外部默认访问不到，需把宿主端口映射到容器端口：

```bash
docker run -d -p 8080:80 nginx          # 宿主 8080 → 容器 80
docker run -d -p 127.0.0.1:8080:80 nginx # 只绑宿主回环，仅本机可访问
docker run -d -p 8080:80 -p 443:443 nginx
docker run -d -P nginx                  # 随机映射 EXPOSE 声明端口
```

> `-p 宿主:容器`。应用要监听 `0.0.0.0` 才能被映射访问到（回看 [[08-构建你的第一个镜像]] 的坑）。

### 5. 容器互联实战

```bash
docker network create appnet
docker run -d --name db --network appnet -e POSTGRES_PASSWORD=123 postgres:16
docker run -d --name api --network appnet -p 8080:8080 myapi:1.0
# api 容器里直接用主机名 db 连接：postgresql://db:5432/...
```

### 6. host 网络

```bash
docker run -d --network host nginx
# 直接用宿主 80 端口，无需 -p 映射；少一层 NAT，性能略好
# 代价：端口与宿主冲突风险，且失去网络隔离
```

### 7. 网络排查

```bash
docker network inspect mynet     # 看连在上面的容器与 IP
docker network connect mynet web # 把运行中容器接入某网络
docker network disconnect mynet web
docker exec -it web ping db      # 测互通
docker exec -it web nslookup db  # 测 DNS 解析
```

### 8. 与外部/宿主通信

- 容器访问宿主：在 Linux 上可用宿主网关 IP（通常是 `172.17.0.1`）；Docker Desktop（Win/Mac）用特殊 DNS 名 `host.docker.internal`。
- 多机通信：用 overlay 网络（Swarm）或交给 Kubernetes（见 [[14-生产环境最佳实践]]）。
