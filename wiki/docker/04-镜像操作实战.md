# 04 镜像操作实战

## 摘要

镜像的「增删改查」全部围绕 `docker image` 子命令（旧式 `docker images` 等仍可用）。本文覆盖拉取、列出、打标签、删除、导出导入、清理，以及镜像分层与体积优化的基本认知。

## 正文

### 1. 查看本地镜像

```bash
docker images                 # 或 docker image ls，列出本地镜像
docker images nginx           # 只看 nginx 相关
docker image ls -a            # 含中间层（构建缓存层）
```

输出字段：`REPOSITORY`、`TAG`、`IMAGE ID`（前 12 位，可缩写为前几位）、`CREATED`、`SIZE`。

### 2. 拉取镜像

```bash
docker pull nginx:1.27        # 指定标签，推荐
docker pull python:3.12-slim  # 拉精简版（基于 debian-slim，体积小）
docker pull alpine:3.20       # 极小基础镜像（~5MB）
```

> 标签选择原则：优先 `*-slim` / `alpine` 减小体积；生产锁定具体版本号，不用 `latest`。

### 3. 搜索镜像（远程）

```bash
docker search nginx          # 从 Docker Hub 搜（功能有限，建议在 hub.docker.com 网页搜）
```

### 4. 打标签（重命名 / 准备推送）

```bash
docker tag nginx:1.27 myregistry.com/myteam/nginx:1.27
# 同一个 IMAGE ID 可以有多个标签，标签只是引用，不占额外空间
```

### 5. 删除镜像

```bash
docker rmi nginx:1.27        # 或 docker image rm <id>
docker rmi -f <id>           # 强制删（若有容器引用，建议先删容器）
docker image prune           # 删所有「悬空」镜像（无标签的 dangling）
docker image prune -a        # 删所有未被容器使用的镜像（谨慎！）
```

> **悬空镜像（dangling）**：构建中产生、标签被新镜像顶替后留下的 `<none>:<none>` 层，可用 `prune` 清理释放空间。

### 6. 导出与导入（离线搬运）

```bash
# 导出成一个 tar 文件（含所有层）
docker save my-nginx:1.27 -o my-nginx.tar
# 在另一台机器导入
docker load -i my-nginx.tar
```

> `save/load` 是整镜像打包；与之对应的是 `export/import`（对**容器文件系统**打包，会丢失历史层与元数据，见 [[05-容器生命周期管理]]）。

### 7. 查看镜像详情与历史

```bash
docker image inspect nginx:1.27   # 看配置、环境变量、入口命令等 JSON
docker history nginx:1.27         # 看每一层由哪条指令生成、各层大小
```

`docker history` 很重要——它能让你一眼看穿一个镜像「胖」在哪一层，是体积优化的起点。

### 8. 镜像体积与分层认知

- 镜像是**只读层叠加**，上层覆盖下层同名文件。
- 多条 `RUN apt-get install` 会生成多层；应合并成一条并用 `&&` 连接、最后 `apt-get clean` 清缓存。
- 精简手段：选小基础镜像、合并 RUN、用 `.dockerignore` 排除无关文件（详见 [[07-Dockerfile完全指南]]）。

### 9. 批量清理（释放磁盘）

```bash
docker system df       # 查看 docker 占用的磁盘分布
docker system prune    # 清理：停止的容器 + 悬空镜像 + 未用网络 + 构建缓存
docker system prune -a # 更狠：连同未被使用的镜像一起删（确认无误再用）
```

> CI/CD 机器常因构建缓存堆积爆盘，定期 `prune` 是必要的运维动作。
