# 12 实战：全栈应用编排

## 摘要

把前面学的串起来：用一个 `compose.yaml` 同时编排 **前端 Nginx + 后端 API + PostgreSQL + Redis** 四个服务，实现「一条命令拉起整套环境」。这是日常开发与演示最典型的落地形态。

## 正文

### 场景设定

- `web`：Nginx 提供静态前端 + 反向代理到 api。
- `api`：Python/FastAPI 后端，连 postgres 与 redis。
- `db`：PostgreSQL 存业务数据（卷持久化）。
- `redis`：缓存（数据可丢，用匿名/命名卷均可）。

### 目录结构

```
project/
├── compose.yaml
├── .env
├── api/
│   ├── Dockerfile
│   ├── requirements.txt
│   └── main.py
├── web/
│   └── nginx.conf
└── frontend/
    └── index.html   (构建产物或静态文件)
```

### compose.yaml

```yaml
services:
  web:
    image: nginx:1.27-alpine
    ports: ["80:80"]
    volumes:
      - ./web/nginx.conf:/etc/nginx/nginx.conf:ro
      - ./frontend:/usr/share/nginx/html:ro
    networks: [appnet]
    depends_on: [api]

  api:
    build: ./api
    environment:
      - DATABASE_URL=postgresql://appuser:${DB_PASSWORD}@db:5432/appdb
      - REDIS_URL=redis://redis:6379/0
    networks: [appnet]
    depends_on:
      db: { condition: service_healthy }
      redis: { condition: service_started }
    restart: unless-stopped

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: appuser
      POSTGRES_PASSWORD: ${DB_PASSWORD}
      POSTGRES_DB: appdb
    volumes:
      - dbdata:/var/lib/postgresql/data
    networks: [appnet]
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U appuser -d appdb"]
      interval: 10s
      timeout: 5s
      retries: 5

  redis:
    image: redis:7-alpine
    networks: [appnet]

volumes:
  dbdata:

networks:
  appnet:
```

`.env`：

```
DB_PASSWORD=change_me_strong
```

`web/nginx.conf`（反向代理到 api）：

```nginx
events { worker_connections 1024; }
http {
  server {
    listen 80;
    location /api/ {
      proxy_pass http://api:8000/;
      proxy_set_header Host $host;
    }
    location / {
      root /usr/share/nginx/html;
    }
  }
}
```

`api/Dockerfile`：

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
EXPOSE 8000
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
```

### 启动与验证

```bash
cd project
docker compose up -d --build      # 构建 api 镜像并拉起全部
docker compose ps                 # 确认 4 个服务 healthy/running
docker compose logs -f api        # 跟踪后端日志
# 浏览器打开 http://localhost 看前端，http://localhost/api/health 看后端
```

### 关键点复盘

- **服务名即主机名**：api 容器用 `db`、`redis` 直接连，依赖自定义网络 `appnet`（见 [[10-容器网络]]）。
- **数据不丢**：`dbdata` 卷把 PostgreSQL 数据落到容器外（见 [[09-数据持久化Volume与挂载]]）。
- **启动顺序**：`depends_on + healthcheck` 保证 api 等 db 真正就绪。
- **配置外置**：密码走 `.env`，不写死进镜像。

### 常见故障

- 后端连不上 db：检查 `DATABASE_URL` 主机名是否为服务名 `db`、`depends_on` 是否等健康。
- 前端 502：`nginx.conf` 里 `proxy_pass` 地址应为 `http://api:8000`，不是 `localhost`。
- 改了代码没生效：`docker compose up -d --build` 重新构建；或开发时把源码 bind mount 进容器。
