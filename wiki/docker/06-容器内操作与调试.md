# 06 容器内操作与调试

## 摘要

容器跑起来后，最常做的是「进去看看」和「为什么挂了」。本文覆盖 `exec` 进容器执行命令、`logs` 看日志、`cp` 拷文件、`attach`/`stats`/`top` 等排查手段，构成日常调试的完整工具箱。

## 正文

### 1. docker exec —— 进容器执行命令

`exec` 在**运行中的容器**里另起一个进程，是调试主命令。

```bash
# 进入交互式 shell（最常用）
docker exec -it web bash
# 若镜像没有 bash（如 alpine），用 sh
docker exec -it web sh

# 不进交互，直接执行一条命令看结果
docker exec web ls /usr/share/nginx/html
docker exec web cat /etc/nginx/nginx.conf

# 以 root 身份进（即使容器以其他用户跑）
docker exec -u root -it web bash
```

> `-i` 保持 stdin 打开，`-t` 分配伪终端。单纯跑命令（如 `cat`）可只给 `-i` 或都不给。

### 2. docker logs —— 看容器日志

容器的「标准输出/错误」由 Docker 接管，用 `logs` 查看：

```bash
docker logs web                 # 看全部日志
docker logs -f web              # 持续跟踪（类似 tail -f）
docker logs --tail 100 web      # 只看最后 100 行
docker logs -t web              # 带时间戳
docker logs --since 30m web     # 看最近 30 分钟
docker logs --until 2026-09-17T10:00 web
```

> 排查「容器起不来 / 秒退」第一反应就是 `docker logs <name>`——往往直接告诉你报错。

### 3. docker cp —— 宿主机与容器间拷文件

```bash
docker cp ./local.conf web:/etc/app/conf.yml   # 宿主 → 容器
docker cp web:/var/log/app.log ./app.log       # 容器 → 宿主
```

> 临时改配置排查可用 `cp`，但**最终改动应写进 [[07-Dockerfile完全指南|Dockerfile]] 或挂载配置文件**（见 [[09-数据持久化Volume与挂载]]），否则容器重建即丢失。

### 4. docker attach —— 附着到主进程

```bash
docker attach web
```

> `attach` 连的是容器的**主进程 stdin/stdout**，按 `Ctrl+C` 可能连主进程一起杀掉。多数情况用 `exec` 更安全，`attach` 仅用于看前台输出。

### 5. 资源与进程查看

```bash
docker top web            # 容器内进程列表（类似宿主 ps）
docker stats web          # 实时 CPU/内存/网络/块 IO
docker diff web           # 看容器可写层相对镜像改了哪些文件（A 增/C 改/D 删）
```

`docker diff` 很实用：想知道容器里「偷偷改了啥」，一眼可见。

### 6. 调试「起不来的容器」套路

```bash
# 1) 先看日志
docker logs myapp

# 2) 若日志为空/秒退，用 --rm 临时用同镜像跑个 shell 手动复现
docker run --rm -it myapp:1.0 sh
  > 手动执行 ENTRYPOINT 看报错

# 3) 改了配置想立刻验证，可覆盖入口
docker run --rm -it --entrypoint bash myapp:1.0
```

### 7. 健康检查与等待

- 用 `docker inspect` 看 `State.Health.Status`（需镜像定义了 HEALTHCHECK，见 [[07-Dockerfile完全指南]]）。
- 等待依赖服务就绪的常见做法：在 Compose 里用 `depends_on` + `condition: service_healthy`（见 [[11-Docker-Compose编排]]）。
