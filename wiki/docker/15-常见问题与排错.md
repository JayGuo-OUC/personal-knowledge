# 15 常见问题与排错

## 摘要

把高频故障汇总成「症状 → 原因 → 解决」清单，并给一套通用的排查思路。遇到怪问题先按本文顺序走一遍，能解决 80% 的情况。

## 正文

### 一、通用排查思路（先记住这个顺序）

1. `docker ps -a` —— 容器到底在不在、状态是什么（Exited？Restarting？）。
2. `docker logs <name>` —— 看报错（**第一现场**）。
3. `docker inspect <name>` —— 看 IP、挂载、配置是否正确。
4. `docker stats` —— 是否吃满 CPU/内存被 OOM 杀掉。
5. 单独用同镜像跑 shell 手动复现（`docker run --rm -it --entrypoint sh img`）。

### 二、高频问题与解决

| 症状 | 可能原因 | 解决 |
|------|---------|------|
| `docker: command not found` | 没装/没启动 Docker | 重装或启动 Docker Desktop / `systemctl start docker` |
| `permission denied` (Linux) | 当前用户不在 docker 组 | `sudo usermod -aG docker $USER` 后重登；或临时 `sudo` |
| 拉镜像超时/极慢 | 国内直连 Docker Hub | 配镜像加速器（见 [[02-安装与环境配置]]） |
| 容器秒退（Exited 0/1） | 主进程跑完即退 / 启动报错 | `docker logs` 看报错；前台命令需长驻（如 `npm start` 而非 `node -e`） |
| 端口映射了仍访问不到 | 应用监听 `127.0.0.1` | 改监听 `0.0.0.0`（见 [[08-构建你的第一个镜像]]） |
| 容器间不能用名字互访 | 在默认 bridge 上 | 改用自定义网络（见 [[10-容器网络]]） |
| 数据重启后没了 | 写在容器可写层 | 挂 Volume（见 [[09-数据持久化Volume与挂载]]） |
| `COPY failed: no such file` | 上下文/相对路径错 | 确认相对 WORKDIR 的路径、`.dockerignore` 没误排除 |
| 构建慢、缓存老失效 | 源码在依赖前 COPY | 先 COPY 依赖清单安装，再 COPY 源码（见 [[07-Dockerfile完全指南]]） |
| 镜像体积巨大 | 没合并 RUN / 含编译工具链 | 多阶段构建 + 合并清理（见 [[07-Dockerfile完全指南]]） |
| `device or resource busy` | 卷被占用删不掉 | 先 `docker stop/rm` 占用容器 |
| 磁盘爆满 | 构建缓存/悬空镜像堆积 | `docker system prune -a`（确认后用） |
| Compose `depends_on` 后仍连不上 db | 只等启动不等就绪 | 用 `healthcheck + condition: service_healthy` |

### 三、容器 OOM（被杀死）

```bash
# 看是否 OOMKilled
docker inspect -f '{{.State.OOMKilled}}' <name>   # 返回 true 即被内存杀
```

→ 调大 `--memory` 或优化应用内存占用。

### 四、进不去容器（无 bash/sh）

```bash
docker exec -it <name> sh          # alpine 无 bash，用 sh
docker exec -it <name> /bin/sh
```

### 五、清理「僵尸」资源

```bash
docker container prune     # 删所有已停止容器
docker image prune -a      # 删未使用镜像
docker volume prune        # 删未使用卷（会丢数据！确认）
docker network prune       # 删未使用网络
docker system prune -a     # 以上全做（最狠）
```

### 六、Windows / WSL2 特有问题

- `docker` 在 PowerShell 找不到：Docker Desktop 没开 WSL Integration，去设置打开对应发行版。
- 文件挂载权限怪：WSL2 下跨文件系统权限映射问题，尽量把项目放在 WSL 家目录而非 `/mnt/c`。
- 端口被占：`bind: address already in use` —— 换宿主端口或停掉占用进程。

### 七、排错心法

- **先看日志，别猜**：90% 的「起不来」`docker logs` 直接给答案。
- **缩小变量**：用最小镜像/最小命令复现，再逐步加复杂度。
- **善用 inspect**：配置类问题（挂载、网络、环境变量）几乎都能在 `inspect` 里查到真相。
