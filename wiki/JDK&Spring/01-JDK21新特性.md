# JDK 21 新特性

## 摘要

JDK 21（2023-09-19 GA）是继 JDK 17 之后的**第二个现代 LTS 版本**，也是目前企业升级的主流落点。它把「虚拟线程」「记录模式」「switch 模式匹配」「有序集合」四项正式转正，把 ZGC 升级为分代式，并对外部函数与内存 API、结构化并发、作用域值等云原生/高并发方向做出布局。对后端来说，JDK 21 的核心价值可以压缩成一句话：**用同步的写法，拿到异步的吞吐**（虚拟线程）＋**用更少的内存和更低的延迟跑同样的负载**（分代 ZGC）。

## 正式特性（Final）

### 1. 虚拟线程 Virtual Threads — JEP 444

本次升级中**业务价值最高**的一项。

```java
// JDK 8 时代：1 万并发 = 1 万个平台线程 = 1 万个 1MB 栈 = OOM 风险
// JDK 21：1 百万虚拟线程，写法不变，阻塞几乎免费
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    IntStream.range(0, 100_000).forEach(i ->
        executor.submit(() -> {
            var data = blockingIoCall(i);   // 阻塞时自动卸载，不占 OS 线程
            return process(data);
        })
    );
}
```

| 维度 | 平台线程（JDK 8 模型） | 虚拟线程（JDK 21） |
|------|----------------------|-------------------|
| 载体 | 1:1 映射 OS 线程 | M:N 映射到少量 carrier 线程 |
| 默认栈 | ~1 MB | 按需增长，初始几百字节 |
| 单机可创建量 | 数千级 | 百万级 |
| 阻塞代价 | 占住 OS 线程，上下文切换昂贵 | 挂起并卸载，carrier 线程复用 |
| 代码改造 | 需改写为 Reactor / CompletableFuture | **基本不用改**，同步代码直接受益 |

**不要指望它提升 CPU 密集型任务**——虚拟线程只解决「等待」不解决「算」。另外两类典型坑：
- **线程固定（pinning）**：在 `synchronized` 块或 native 方法内阻塞时，虚拟线程无法卸载。JDK 21 已优化部分场景，但重度 `synchronized` 的老代码需排查（JDK 24 的 JEP 491 才彻底解决）。
- **池化反模式**：虚拟线程**不要池化**，它的创建成本已经极低，池化反而限制吞吐。

### 2. 记录模式 Record Patterns — JEP 440

解构记录类型，配合 instanceof/switch 一步到位。

```java
record Point(int x, int y) {}
record Line(Point start, Point end) {}

// 嵌套解构，一行拿到最内层字段
if (obj instanceof Line(Point(var x1, var y1), Point(var x2, var y2))) {
    System.out.println("斜率 = " + (y2 - y1) / (double)(x2 - x1));
}
```

价值：与 sealed 类组合后，可以写出**编译器可校验穷尽性**的领域建模代码，替代大量 `if-else + 强转`。

### 3. switch 模式匹配 — JEP 441

```java
// sealed + record + switch 模式匹配，编译器保证分支穷尽
sealed interface Shape permits Circle, Rectangle, Triangle {}
record Circle(double r) implements Shape {}
record Rectangle(double w, double h) implements Shape {}
record Triangle(double a, double b, double c) implements Shape {}

double area(Shape s) {
    return switch (s) {
        case Circle c    -> Math.PI * c.r() * c.r();
        case Rectangle r -> r.w() * r.h();
        case Triangle t  -> { var p = (t.a()+t.b()+t.c())/2;
                              yield Math.sqrt(p*(p-t.a())*(p-t.b())*(p-t.c())); }
        // 无需 default：sealed 保证穷尽
    };
}
```

另含 **守卫模式**（`case Circle c when c.r() > 10 ->`）与 null 处理（`case null ->`）。

### 4. 有序集合 Sequenced Collections — JEP 431

给「有确定遍历顺序」的集合补上了统一的头尾操作 API。`List` 拿 `getFirst()/getLast()/addFirst()/addLast()/reversed()`，`Deque`、`LinkedHashSet`、`TreeMap` 等同样受益，终结了 `list.get(list.size()-1)` 这种写法。

```java
var seq = new LinkedHashSet<String>(List.of("a", "b", "c"));
seq.getFirst();        // "a"
seq.reversed();        // [c, b, a] 视图，不拷贝
```

### 5. 分代 ZGC — JEP 439

ZGC 从「不分代」升级为「分代」，把堆划分为年轻代与老年代，从而**大幅降低 GC 扫描开销、减少内存占用放大**。

| GC | 停顿量级 | 适用 |
|----|---------|------|
| Parallel GC | 秒级（JDK 8 默认） | 吞吐优先、可容忍长停顿 |
| G1 GC | 十~百毫秒（JDK 9+ 默认） | 通用默认，平衡型 |
| 分代 ZGC | **亚毫秒**（通常 < 1ms） | 大堆 + 低延迟 SLA |
| Shenandoah | 亚毫秒~毫秒 | 低延迟，与 ZGC 二选一 |

开启：`-XX:+UseZGC`（JDK 21 默认即分代）。适合工业物联、水务遥测这类**持续高频写入 + 抖动敏感**的场景。

### 6. 外部函数与内存 API（第三次预览）— JEP 442

`java.lang.foreign` 提供**安全、纯 Java** 的堆外内存访问与本地库调用，用来替代 `sun.misc.Unsafe` 和 JNI。对需要使用国产密码库、硬件 SDK、工业协议 native 库的政企项目，这是摆脱 JNI 胶水层的正道。

### 7. 密钥封装机制 API — JEP 452

KEM（Key Encapsulation Mechanism）API，为**后量子密码（PQC）**迁移做准备。对有密码合规要求的政务/水务系统，属于提前卡位能力。

## 预览 / 孵化特性（谨慎用于生产）

| JEP | 特性 | 状态 | 说明 |
|-----|------|------|------|
| 453 | 结构化并发 Structured Concurrency | 预览 | 把一组并发任务当作一个工作单元，统一取消/超时，避免线程泄漏 |
| 446 | 作用域值 Scoped Values | 预览 | ThreadLocal 的现代化替代，配合虚拟线程，开销更低、生命周期明确 |
| 443 | 未命名模式与变量 | 预览 | `_` 占位，简化模式匹配 |
| 445 | 未命名类与实例 main 方法 | 预览 | 简化 Hello World，教学友好 |
| 448 | Vector API | 第六次孵化 | SIMD 向量计算 |
| 430 | 字符串模板 | 预览 | **注意：JDK 23 已被移除**，不要在新代码中采用 |

> 生产代码**不建议依赖预览特性**（需 `--enable-preview`，且跨版本不保证兼容）。但**结构化并发 + 作用域值**这两项值得跟踪——它们与虚拟线程是一套组合拳。

## 移除与行为变更（升级时的雷）

| 项 | 变更 |
|----|------|
| 模块强封装 | JDK 16 起 `--illegal-access` 默认 deny，反射 JDK 内部类直接抛 `InaccessibleObjectException`（Lombok、各类反射工具重灾区） |
| JAXB / JAX-WS / CORBA | JDK 11 已从 JDK 移除，需显式加 Maven 依赖（这反而简化了 jakarta 迁移） |
| Nashorn JS 引擎 | JDK 15 移除 |
| CMS GC | JDK 14 移除 |
| RMI Activation | JDK 15 移除 |
| SecurityManager | JDK 17 标记废弃，计划移除 |
| Windows 32 位 | JEP 449 标记废弃 |
| 动态加载 Agent | JEP 451，默认警告，为将来默认禁止做准备（影响部分 APM 探针挂载方式） |
