# 技能：主题知识库搭建

## 适用场景

需要为某个主题（如「云原生」「Git」「JDK & Spring 升级」）快速搭建一套结构化、互相链接的条目集合时。
主题既可以是**学习/研究型**（由浅入深的系统教程），也可以是**决策型**（围绕一次技术选型/迁移，产出对比、路径、论证）。

## 输入

- 主题名称
- **主题类型**：`学习教程型` / `决策选型型`
- 条目数量与各自范围（用户常会直接给出清单）
- （可选）已有的原始资料、书籍、课程链接

## 步骤

1. **读规则与现有约定**：先读根 `CLAUDE.md`（标准格式 / 新开 vs 并入 / 双链规则），再读一个已有主题索引（如 `wiki/云原生/云原生-index.md`）和一篇已有条目，对齐文件命名与文风。
2. **⚠️ 版本/事实核查（决策型主题必做，学习型建议做）**：若主题涉及技术版本（框架、语言、工具链）且用于**实际选型或排期**，动笔前必须联网核实当前版本、支持周期与许可状态。模型的训练知识很可能已过期，过时结论会直接误导决策。核查至少覆盖：当前稳定版本、EOL 日期、最低依赖版本、许可变更节点。
3. **若核查结果与用户描述冲突，以核查为准并在回复中说明**。例：用户说「升到 Spring 3」，但 3.x 全系已 EOL → 应主动修正为 4.x 并给出依据。
4. **规划条目清单**：
   - 学习教程型：基础 → 核心 → 进阶 → 路线
   - 决策选型型：特性清单 → 版本对比 → 迁移路径 → 论证（含风险与收益）
5. 按 [[CLAUDE]] 第二节的标准格式写每篇：`frontmatter + 摘要 + 正文 + 相关（双链）+ 来源`。摘要 2–4 句，扫一眼就懂这条讲什么。
6. 条目间用 `[[双链]]` 互引，每篇 `## 相关` 至少 2 个链接；**主动跨主题关联**已有主题，别只在本主题内自循环。
7. 写**主题索引页**（`wiki/<主题>/<主题>-index.md`）：一句话结论 / 条目目录 / 推荐阅读顺序 / 跨主题关联。决策型主题另加**关键时间节点表**。
8. 更新**总索引** `wiki/index.md`（新增主题 + 主题数 + 条目数）。
9. 跑**链接完整性检查**（脚本遍历 `[[...]]`，比对全库 md 文件名），消除断链与孤儿页。
10. 在 `wiki/log.md` 记一笔：日期 + 操作类型 + 做了什么 + 联动更新了哪些文件 + 核查时点。

## 注意事项

- 链接目标不存在先建**占位页**，再回填链接，不留悬空链接。
- **双链要写带序号的完整文件名**（如 `[[01-JDK21新特性]]`），因为 Obsidian 未启用「标题/basename 匹配」，写 `[[JDK21新特性]]` 会指向不存在的文件。
- 只写 wiki 已有内容，不编造。
- 不要把 AI 生成的教程当成用户的写作风格（参见 [[CLAUDE]] 第五节）。
- 新主题用并列文件夹/主题索引管理，不要和已有主题混在一起。
- 决策型主题要给出**可执行的下一步**（路线图、工时估算、风险对冲表），不要只堆特性清单。
- 涉及许可/合规的内容（如 Oracle JDK 免费期到期），要给出**规避方案**而非只提示风险。

## 链接校验脚本

```bash
cd <vault根目录> && python -c "
import re, pathlib
root = pathlib.Path('.')
names = {p.stem for p in root.rglob('*.md')}
bad, total = [], 0
for p in sorted((root/'wiki'/'<主题文件夹>').glob('*.md')):
    for t in re.findall(r'\[\[([^\]\|#]+)', p.read_text(encoding='utf-8')):
        total += 1
        if t.strip() not in names: bad.append((p.name, t.strip()))
print('链接总数:', total, '| 断链数:', len(bad))
[print('  ', f, '->', t) for f, t in bad]
"
```
