# 代码评审门禁

## 何时使用

- 用户明确要求「评审 / 审查 / 审计 / 检查」代码
- 提交 PR 前、合并前的把关
- 评审 AI 生成的代码（**必过此门禁**）
- 改动涉及安全、鉴权、数据处理、外部接口时

## 步骤

### 1. 确定评审范围

```bash
git status --porcelain
git diff --name-only
git diff --stat
```

优先级：**改动文件 > 改动文件的直接调用方 > 无关文件**。不要一上来就通读全仓库。

### 2. 读取评审清单

**逐维度检查前，先读 `references/review-checklist.md`**，那里有每一维的详细检查项与代码正反例。

### 3. 逐维度过一遍

对每份改动文件，按六维打分：

| 维度 | 核心问题 |
|------|---------|
| 🔴 **安全** | 有没有注入、越权、XSS、CSRF、不安全的反序列化？ |
| 🔴 **敏感信息泄露** | 密钥、个人信息、堆栈、内网地址会不会泄露？ |
| 🔴 **合规** | 有没有数据出境、境外依赖、违反行业规定？ |
| 🟠 **性能** | 有没有 N+1 查询、循环内 IO、无界内存增长、缺失索引？ |
| 🟡 **可维护性** | 命名、圈复杂度、重复代码、错误处理、注释质量 |
| 🟡 **依赖** | 新依赖是否必要、是否有已知漏洞、许可证是否合规 |

### 4. 判定与输出

严重度分级：

| 等级 | 含义 | 处理 |
|------|------|------|
| **Blocker** | 安全漏洞 / 数据泄露 / 合规红线 | **必须修复，不得合并** |
| **Major** | 明确缺陷、性能问题、明显坏味道 | 应当修复 |
| **Minor** | 命名、格式、可读性 | 可选 |
| **Nit** | 吹毛求疵 | 随意 |

输出固定格式（**不得省略任何一段**）：

```markdown
## 代码评审报告

**评审范围**：<文件清单>
**评审依据**：references/review-checklist.md
**结论**：✅ 通过 / ⚠️ 通过但需跟进 / ❌ 有 Blocker，不得合并

### Blocker（必须修复）
| 维度 | 文件:行号 | 问题 | 为什么严重 | 修复建议 |
|------|----------|------|-----------|---------|

### Major
| 维度 | 文件:行号 | 问题 | 修复建议 |
|------|----------|------|---------|

### Minor / Nit
- <文件:行号>：<问题>

### 逐维结论
| 维度 | 结论 | 说明 |
|------|------|------|
| 安全 | ✅/⚠️/❌ | |
| 敏感信息 | ✅/⚠️/❌ | |
| 合规 | ✅/⚠️/❌ | |
| 性能 | ✅/⚠️/❌ | |
| 可维护性 | ✅/⚠️/❌ | |
| 依赖 | ✅/⚠️/❌ | |

### 值得肯定的地方
- <具体指出写得好的地方>
```

### 5. 留痕

评审报告**必须落盘**，路径：

```
output/评审-<简短描述>-<YYYY-MM-DD>.md
```

落盘后才算评审完成——这是审计要求，不是可选项。

## 示例

**输入**：「评审下 src/api/user.ts 的改动」

**输出（节选）**：

```markdown
### Blocker
| 维度 | 文件:行号 | 问题 | 为什么严重 | 修复建议 |
|------|----------|------|-----------|---------|
| 敏感信息 | src/api/user.ts:42 | `logger.info(req.body)` 打印完整请求体 | 请求体含手机号与身份证号，落日志即泄露个人信息 | 改为白名单字段打印，或脱敏 `maskPhone()` |

### 逐维结论
| 维度 | 结论 | 说明 |
|------|------|------|
| 安全 | ✅ | 参数化查询，无拼接 SQL |
| 敏感信息 | ❌ | 日志泄露个人信息 |
| 合规 | ⚠️ | 新增 `axios` 依赖需确认是否走内网源 |
```

## 边界（Do NOT）

- **不要为了凑数编造问题**——没问题的维度就写 ✅，不要硬找
- **不要直接改代码**——本技能职责是评审，修复需用户确认后另外进行
- **不要用「建议优化」替代具体问题**：每条必须能定位到 `文件:行号`
- **不要跳过「值得肯定的地方」**——评审不是挑刺，好的写法要固化下来
- **评审 AI 生成代码时，额外检查「幻觉依赖」**：AI 常引用不存在的包或 API
- Blocker 一条都不能放过，不存在「先合并后修复」
