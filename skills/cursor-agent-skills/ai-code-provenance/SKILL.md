# AI 代码留痕

## 何时使用

- AI 生成或大改代码之后、提交之前
- 需要向审计/管理层说明「哪些代码是 AI 写的、人有没有看」
- 用户提到留痕、可追溯、审计、AI 声明
- 作为 `code-review-gate` 的**前置或伴随**动作

## 为什么需要

| 没有留痕会怎样 | 有留痕能解决 |
|---------------|-------------|
| 出事后无法定位哪些代码是 AI 写的 | 影响范围可精确圈定 |
| 无法证明「人审过」 | 有评审确认记录，责任清晰 |
| 无法复现当时的生成条件 | 提示词摘要 + 模型 + 日期可追溯 |
| 团队对 AI 代码的信任度不可控 | 留痕率成为可度量指标 |

## 步骤

### 1. 圈定 AI 影响范围

```bash
git status --porcelain
git diff --stat
```

区分三类：

| 类型 | 标记 |
|------|------|
| AI 全新生成 | `ai-generated` |
| AI 修改已有代码 | `ai-modified` |
| 人写的代码 | 不标记 |

只标记**AI 确实动过**的部分，不要整文件贴标签。

### 2. 在代码里加声明

**新建文件**——在文件头加：

```js
/**
 * @ai-generated
 * @model      <模型名，如 claude-sonnet-4 / cursor-composer>
 * @date       YYYY-MM-DD
 * @prompt     <一句化的提示词摘要，不超过 80 字>
 * @reviewed-by <评审人> YYYY-MM-DD
 */
```

**修改已有代码**——在改动处附近加行内注释：

```js
// @ai-modified 2026-09-03 by <模型名> | reviewed by <评审人>
```

规则：
- 声明**简洁**，不写长篇说明
- `@prompt` 只写摘要，**不得包含敏感信息**（不写业务数据、不写密钥、不写客户名）
- 评审人必须填**真人**，未评审就留空并标 `pending`

### 3. 生成留痕记录

写入 `output/AI代码留痕-<YYYY-MM-DD>.md`：

```markdown
# AI 代码留痕 · YYYY-MM-DD

## 概要
- 涉及文件：N 个
- 其中 AI 全新生成：X 个 / AI 修改：Y 个
- 使用模型：<模型名>
- 提示词摘要：<一句话，脱敏>
- 人工评审状态：✅ 已完成 / ⏳ 待评审

## 明细
| 文件 | 类型 | 改动说明 | 提示词摘要 | 评审人 | 评审日期 |
|------|------|---------|-----------|--------|---------|

## 人工评审确认
- [ ] 我（评审人）已逐行阅读上述 AI 产出的代码
- [ ] 已理解其逻辑，确认无明显安全/合规问题
- [ ] 已确认无数据出境与敏感信息泄露
- [ ] 已运行验证（测试/构建/手工验证），结果符合预期
- [ ] 无「幻觉依赖 / 幻觉 API」

**评审人**：______  **日期**：______
```

### 4. 提交信息里体现

commit message 里加标记（与 `commit-and-pr` 技能配合）：

```
feat(user): 新增用户导入功能

AI-assisted: claude-sonnet-4 | 提示词: 实现 Excel 导入并校验手机号格式
Reviewed-by: 张三
```

### 5. 校验留痕完整性

```bash
# 找出未留痕的 AI 改动（人工比对 git diff 与留痕记录）
git diff --name-only
```

检查：
- [ ] 每个 AI 动过的文件都有声明
- [ ] 每条声明都填了模型与日期
- [ ] 评审人不为空（或明确标 `pending`）
- [ ] 留痕记录已落盘

## 示例

**输入**：「给刚才 AI 生成的导入功能加留痕」

**输出**：

```markdown
# AI 代码留痕 · 2026-09-03

## 概要
- 涉及文件：2 个
- 其中 AI 全新生成：1 个 / AI 修改：1 个
- 使用模型：cursor-composer
- 提示词摘要：实现用户 Excel 导入，校验手机号与身份证格式，失败行单独收集报错
- 人工评审状态：⏳ 待评审

## 明细
| 文件 | 类型 | 改动说明 | 评审人 | 评审日期 |
|------|------|---------|--------|---------|
| src/features/user/import.ts | ai-generated | Excel 导入与校验主体逻辑 | pending | — |
| src/features/user/index.ts | ai-modified | 注册导入入口 | pending | — |
```

## 边界（Do NOT）

- **提示词摘要里不得出现敏感信息**（密钥、客户名、真实业务数据、内网地址）
- **不要用留痕替代评审**——留痕只证明「标记了」，评审才证明「看过了」
- **不要给 AI 没动过的文件贴标签**，会稀释留痕的价值
- **不要自动填评审人**——必须真人署名，这是留痕的意义所在
- 评审未完成的，**允许标注 `pending` 但不得冒充已完成**
